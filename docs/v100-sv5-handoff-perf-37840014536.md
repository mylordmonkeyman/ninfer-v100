# SV5 early route handoff: production HTTP A/B (no clear win)

**Run:** https://github.com/mylordmonkeyman/ninfer-v100/actions/runs/37840014536; frozen source `f33b19d3ec54e5aebc4fcfe32297243848324d1e`; evidence artifact `11578102450`. Hardware job succeeded; hosted checks succeeded.

Three fresh-process repetitions per arm and MTP setting; identical resident 113 GB mixed-quant NInfer model, BF16 KV, 64 static GPU expert-cache slots/layer, grouped CPU misses, device route combine, ~1024–2048-token first HTTP request, 64 generated tokens and prefix replay/continuation controls. Route-handoff arm uses the existing early router-event transfer path in prefill only; stream-experts path is disabled by its present interface contract. The installed Strata and source weights were untouched.

| Cold request | Serial TTFT median | Handoff TTFT median | Serial prefill tok/s | Handoff prefill tok/s |
|---|---:|---:|---:|---:|
| No MTP | **15.092 s** | 15.371 s | **81.313** | 79.840 |
| MTP | 15.235 s | **15.204 s** | 80.553 | **80.723** |

For no-MTP cold HTTP, early handoff is 1.8% slower on TTFT. With MTP, it is only 0.2% faster, below ordinary cross-process variation. Continuation timing also varies without a convincing consistent benefit. All qualification/route-handoff fixtures in this campaign passed, but this benchmark does **not** demonstrate an end-to-end speedup. The final original BF16/SIMT path is preserved.

**Decision:** SV5 event-based handoff remains opt-in. Do not promote as default or chase sub-percent effects. Current evidence is limited to 1K–2K prefill and fixed64/BF16-CPU-cache, not a 16K–32K stream-experts workload. Resume SV6/ SV7 priorities in the original specification. Data and raw requests: linked artifact.
